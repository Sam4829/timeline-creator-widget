# Timeline Estimator Developer Guide

Welcome to the internal mechanics of the Timeline Estimator Figma Plugin! This guide is designed to help you quickly understand the codebase, make modifications, and extend the plugin with new features. 

The plugin is built with TypeScript and Preact using the `@create-figma-plugin` toolchain.

---

## 1. Architecture Overview

Like all Figma plugins, Timeline Estimator operates across two separate environments that communicate via message passing:

1. **The Figma Sandbox (`src/main.ts`)**: Has direct access to the Figma DOM to create layers (frames, text, rectangles) and position them on the canvas. It cannot make network requests or render complex HTML UIs.
2. **The Iframe UI (`src/ui.tsx`)**: A standard browser environment that displays the plugin window. It contains all the Preact components and logic to manage the user's data before generation.
3. **Configuration (`package.json`)**: Ties the plugin together by defining the entry points and required permissions inside the `"figma-plugin"` key. The `manifest.json` is auto-generated by `@create-figma-plugin/build` — do not edit it manually.

**The Main Workflow**: The user interacts with `src/ui.tsx` to configure their table structure. Upon clicking "Generate Timeline", the UI sends the configuration to `src/main.ts`, which then parses the data and programmatically draws the table on the canvas.

## 2. UI and State Management (`src/ui.tsx`)

The frontend uses Preact components with TypeScript.

### Type Definitions (`src/types.ts`)
The plugin state is modeled with these TypeScript interfaces:
```typescript
export interface PluginData {
  projectName: string
  columns: Column[]
  rows: Row[]
  theme: 'dark' | 'light'
}
```
*Note: The `cells` array in each row maps directly by index to the `columns` array.*

### UI Structure
* The UI uses a tabbed structure (`Setup`, `Structure`, `Plan Details`, `Preview`) managed by the `activeTab` state.
* `handleGenerate`: Formats the dates appropriately and emits the timeline generation event to the sandbox environment.

## 3. Figma Sandbox Execution (`src/main.ts`)

When `src/main.ts` receives the generate command, it performs several heavy lifting operations to ensure the generated table looks native and robust:

### Dynamic Font Resolution
Figma requires fonts to be explicitly loaded (`figma.loadFontAsync()`) before they can be applied to text nodes. Since we can't guarantee a user has a specific font installed, `resolveFonts()` handles this gracefully:
1. It queries `figma.listAvailableFontsAsync()`.
2. It loops through a priority list of preferred families (Inter, Roboto, SF Pro, Helvetica, etc.) to find a match.
3. It maps our logical font weights (`regular`, `medium`, `semibold`, `bold`) to whatever arbitrary style names that specific font uses natively (e.g. mapping `semibold` to `Semi Bold` or `DemiBold`). 
*(Fallback: If absolutely none of the priority fonts are found, it safely falls back to the very first font available on the user's system).*

### Canvas Generation
The `drawTimeline(data)` function takes the configuration payload and sequentially builds the table:
1. **Coordinate Calculation**: It calculates the required widths based on column types and the total height based on row counts.
2. **Safe Positioning**: It scans `figma.currentPage.children` to find the right-most bounding box (`maxX`). It drops the new table at `maxX + 100` so it never overlaps existing work.
3. **Drawing Components**: Uses `figma.createFrame()`, `figma.createText()`, and a helper `addRect()` (for borders).
4. **Specific Cell Logic**: Truncates task names, formats text, and draws pill-shaped components for `status` column types using the hex colors defined in the `DARK` and `LIGHT` config objects.
5. **Camera Zoom**: Finally, it calls `figma.viewport.scrollAndZoomIntoView()` to focus the user's camera on the generated table.

## 4. Inter-Process Communication

Data moves between the two environments using typed event handlers from `@create-figma-plugin/utilities` (`emit` and `on`).

**Iframe -> Sandbox**
When the user clicks "Generate", `src/ui.tsx` gathers the state and fires:
```typescript
emit<GenerateTimelineHandler>('GENERATE_TIMELINE', { ...payload })
```
In `src/main.ts`, this is intercepted by:
```typescript
on<GenerateTimelineHandler>('GENERATE_TIMELINE', async function (data: PluginData) { ... })
```

**Sandbox -> Iframe**
Once `src/main.ts` completes the drawing (or catches an error), it notifies the UI:
```typescript
emit('GENERATE_SUCCESS', { nodeId: result.nodeId, fontUsed: ... })
```
In `src/ui.tsx`, this is intercepted by a handler which can then update the UI state.

## 5. How to Extend the Plugin

Here are quick guides for common customizations:

### Adding a New Template
1. Open `src/ui.tsx` and locate the `handleTemplateChange` function.
2. Add a new if-branch for your template containing column definitions and initial rows.
3. Add the template name to the `templateOptions` array.

### Adding a New Status Option
1. Open `src/ui.tsx` and find the status dropdown options inside the row rendering block. Add your new status to the options array.
2. Open `src/main.ts` and update both `DARK_THEME.statusColors` and `LIGHT_THEME.statusColors` with your new `{ bg, fg }` hex codes.

### Adding a New Column Type
1. **In `src/ui.tsx`**:
   * Add the option to `typeOptions`.
   * In the row rendering block, add a new branch to render the specific input cell.
2. **In `src/main.ts`**:
   * Update the width assignment logic inside `drawTimeline()` to give your new type a specific pixel width (`colWidths.push(...)`).
   * Update the data rendering logic inside the nested loop of `drawTimeline()` to handle drawing the specific Figma nodes for your new type.
